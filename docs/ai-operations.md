# AI 自动运维

进入侧栏 **AI 运维**，先点击 **AI 接口**，配置基础地址、模型和 API Key。接口支持提供 Chat Completions 函数工具调用的 OpenAI 兼容服务。基础地址通常以 `/v1` 结尾，系统追加 `/chat/completions`；本地模型服务可不填 Key。协议参考 [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

API Key 使用现有主密钥加密保存，读取接口只返回 `key_set`。保存时地址不变且 Key 留空，保留原值；更换接口地址后必须重新输入已保存的密钥，避免误发给其他服务。停用接口会取消当前 AI 执行，并暂停待执行任务；重新启用后，排队任务继续执行。任务读取的文件、运行状态和日志会发送到所配置的模型服务。

## 模型列表与参数

在“AI 接口与模型”中填写地址和 Key，点击“拉取上游模型”，系统请求该地址的 `GET /models`。拉取可使用尚未保存的地址和 Key，也可在地址不变时复用已保存的 Key；拉取操作不会保存配置。搜索并勾选需要启用的模型，再选择默认模型，最后保存。

上游不支持模型列表时，可手动添加模型 ID。刷新列表会保留已有选择及自定义参数，新发现的模型默认不勾选。上游暂时未返回的已配置模型也会保留，不会自动删除。最多保存 200 个模型，模型列表最多接收 5000 项。

每个模型支持：

| 字段 | 用途 |
| --- | --- |
| `id`、`name` | 上游模型 ID 和本地显示名称 |
| `enabled` | 是否允许任务选用 |
| `context_window` | 本地上下文预算，1024–4000000 tokens |
| `max_output_tokens` | 单次回复的最大输出预留，须小于上下文窗口 |
| `temperature` | 可选，0–2；留空不发送此参数 |
| `output_parameter` | 默认 `max_completion_tokens`；旧兼容接口可选 `max_tokens` |

上游若提供 `context_window` / `context_length`、`max_output_tokens`，新模型会参考这些信息初始化。缺失时，页面使用 32768 上下文 / 4096 最大输出作为可编辑的初始配置，**这些值不代表已探测到模型实际容量**，请按服务商文档确认。模型列表本身也不证明模型支持工具调用，请选择兼容的对话模型。

内置引擎每轮请求前，按消息与工具定义的 UTF-8 JSON 字节数加 1024 余量，保守估算输入 token 预算，并预留最大输出；超出窗口时停止并提示调整，不会静默截掉指令、文件或工具结果。这是跨上游 tokenizer 的保守估算，上游实际计数仍以其响应为准。上下文设置只约束本地请求，不改变上游模型的实际容量。Pi 使用 SDK 的上下文管理与自动压缩，使用同一模型的上下文与输出上限。

新建或编辑任务时可选择已启用模型，也可“使用默认模型”。显式指定模型后，如果该模型被停用，任务会失败并提示修改配置，不会自动换用其他模型。执行记录会显示实际使用的模型及预算。旧的单模型配置自动转换为一个已启用模型，原任务继续使用默认模型。

## 创建任务

### Pi 自主运维

新建任务默认选择 **Pi 自主运维**；已有任务保留内置引擎，可编辑切换。Docker 镜像包含锁定版本的 Pi SDK 和 Node。Pi 决定排查步骤、修改方案及重试方式，所有工具经 Go 后端执行并写入执行记录。不会自动加载项目或用户目录中的 Pi 扩展、技能及凭据。模型接口必须支持流式 Chat Completions 与工具调用。

非容器安装还需 Node 24+、在 `pi/` 执行 `npm ci --ignore-scripts`，并将环境变量 `ZHAN_PI_BRIDGE` 指向 `pi/bridge.mjs` 的绝对路径；保留原有 Docker CLI 和 socket 访问能力。

- **允许执行命令和测试**：`run_command` 在临时容器中运行 Shell，工作目录 `/workspace`，只挂载当前项目，不挂载 Docker socket、平台数据库或平台密钥。选择包含 `sh` 和所需 Python / Node / Go 工具的测试镜像；生产环境建议固定镜像摘要。默认镜像 `python:3.13-alpine`。
- 每条命令最多 60 秒，输出最多 32 KiB，容器最多 512 MiB 内存、1 CPU、128 个进程；根文件系统只读，`/tmp` 可写。未授权文件写入时，项目挂载也只读。返回实际退出码、输出截断及超时标记。
- **允许网络**：单独授权测试容器下载依赖或访问网络；未授权时使用 `--network=none`。依赖可装入 `/tmp` 或项目虚拟环境，测试镜像和容器状态不会持久化。Docker 守护进程拉取测试镜像不受容器网络开关限制。
- **允许 Clash 操作**：先在 AI 页面填写控制接口、密钥和允许切换的策略组，再为任务授权。`clash` 工具支持查询代理、节点延迟探测和切换授权组；AI 自主判断是否需要切换，密钥不传入模型。控制地址须能从栈长容器访问。密钥加密保存，换地址须重填。
- Pi 的 `stack_action` 等待队列中任务真实结束，并返回状态和日志，允许在总工具次数预算内再次修复或重试。内置引擎仍只排队且最多提交一个项目操作。任务状态 success 表示 Agent 正常结束；项目是否恢复须查看工具返回的实际状态和最终报告。

取消或超时会终止 Pi 及正在执行的命令容器。已经提交的部署任务继续由现有队列管理，需在部署历史中单独取消；已经修改的文件不会自动回滚。平台异常退出时，Pi 任务恢复为中断状态；异常断电遗留的测试容器需检查清理。容器隔离不替代可信项目管理：可写目录内的硬链接、外部编辑与网络目标仍需管理员合理授权。

### 自动故障排查示例

关联一个正在运行的项目，选择事件触发 `task.failed`，启用自动触发，并按需要授权读写、命令、项目操作和 Clash。在指令中给出目标和约束，例如：

> 自主分析关联项目最近的失败任务与日志。先检查历史，偶发故障只记录；连续失败时尝试恢复。拉取失败时判断网络、认证或仓库状态，必要时检查 Clash、探测节点、切换授权组后重试。构建失败时定位根因，修改必要文件，运行现有测试，不删除或弱化测试，再重新构建并核对运行状态。不要推送代码。无法恢复时明确报告原因、已修改内容和需要人工介入的事项。

阈值和处理步骤由任务指令及 AI 决定，平台不硬编码“失败就切节点”。`stack_status` 提供近期任务和项目失败次数。AI 提交的部署不会递归触发 AI 事件；手动停止的项目仍不可由 AI 启动。测试环境应按项目准备，网络切换不会自动改变未使用该代理的 Git / Docker 网络配置。

使用已经配置的真实模型验证自动修复闭环：`python scripts/check-pi.py`。脚本创建独立项目，故意引入代码错误并触发构建失败，检查自动排查、文件修复、命令测试及实际部署结果；结束后停用测试任务并清理测试容器。完整记录保存在 `.test-runtime/`。Clash 单元测试使用模拟控制器，不操作真实节点。

填写名称、指令和服务器上的工作区绝对路径。可以直接选择关联项目，自动填入项目目录；关联后可查看该项目运行状态及最近部署任务、部署日志。

每个任务分别授权：

- **只读文件**：默认权限，列目录和读取文本文件。
- **允许写入**：创建目录、新建或修改 UTF-8 文本文件。现有文件必须先读取，凭 SHA-256 更新，避免覆盖读取后已变化的内容。单文件限制 32 KiB，父目录须先创建。
- **允许项目操作**：必须关联项目，且工作区等于项目目录。模型可提交 `git_check`、`git_pull`、`deploy`、`rebuild`、`start`、`stop`、`restart`，每次 AI 执行最多提交一个操作。平台手动停止的项目不能由 AI 启动、重启或部署。

内置引擎不提供任意 Shell、文件删除、文件系统根目录之外的工具或 `.git` 元数据编辑。工具返回的“排队”代表已创建部署任务，实际执行状态请查看部署历史；AI 执行成功不代表其提交的部署已完成。

工作区遵循 `allowed_roots`，不能包含栈长数据目录，也不能位于数据目录内。路径使用 Go `os.Root` 限制在工作区内，拒绝绝对路径、越界路径和符号链接；写入通过工作区内临时文件进行原子替换。相同、父子或重叠工作区的 AI 与部署操作互斥；其他项目仍可按 `workers` 并行。外部编辑器、宿主机进程、已有硬链接和挂载点不构成独立的 OS 沙箱，建议选择专用且可信的项目目录。

示例指令：

> 检查 compose.yaml 与最近失败的部署日志，说明失败原因。如果配置问题可以明确修复，则修改对应文件并汇报修改内容；不要修改业务数据。需要重新部署时提交 rebuild，并在报告中列出部署任务 ID。

开启写入和项目操作后，满足任务指令的修改与提交会自动进行。取消任务只停止后续 AI 调用，不回滚已写入的文件；已经提交的部署任务需在部署历史中另行取消。

## 定时任务

支持三种时间配置：

- **仅手动**：保存后点击“立即运行”。
- **按间隔**：60 秒至 30 天，例如每 3600 秒巡检。
- **每天定时**：指定 `HH:MM` 和 IANA 时区，例如 `09:00`、`Asia/Shanghai`。

勾选“启用自动触发”才会自动排队，停用自动触发仍可手动运行。调度状态持久化到 SQLite，每个 AI 任务最多有一条待执行或执行中记录，全局 AI 串行执行，队列最多 100 条。每次完成后再处理新的到期任务，所以繁忙时可能延后；停机错过的间隔不会逐次补跑，到期后补一次并计算下一次时间。

单次执行支持 10–1800 秒超时与 1–50 次工具调用上限。超时包含等待工作区锁的时间。后台 HTTP 请求带上下文取消和 90 秒单请求超时；执行记录上限 256 KiB。文件写入及模型操作不是跨工具事务，失败时请查看已完成步骤。

## 事件任务

选择“事件触发”，填写事件名：

- `task.failed`：任一 Git / 生命周期 / 部署任务失败。
- `task.success`：上述任务成功。
- 自定义事件，例如 `monitor.alert`。

关联项目时只匹配该项目的事件；未关联项目时匹配所有项目。内置事件包含 `task_id`、`task_type`、`status`、`error`。AI 提交的项目操作不再产生 AI 触发事件，也不进入部署指数退避重试，避免自动调用循环；失败后可由管理员检查并重试。

事件和消费游标持久化，创建、保存或重新启用任务时，从当前最新事件开始，不消费更早的历史事件。任务运行期间的新事件会保存，结束后按顺序处理。一次调度中，创建运行记录与推进事件游标在同一数据库事务内完成，避免重启重复入队。

可在页面“发送自定义事件”中测试，也可由已经登录的平台客户端请求：

```http
POST /api/v1/ai/events
Content-Type: application/json
X-CSRF-Token: <登录取得的 csrf_token>
Cookie: zhan_session=<会话>

{"name":"monitor.alert","stack_id":1,"payload":"磁盘使用率达到 90%"}
```

该接口使用与平台其他写接口相同的会话和 CSRF 验证；不提供匿名 Webhook。`payload` 为字符串，最多 16000 字节，`stack_id=0` 表示全局事件。`task.*` 为保留命名空间。

## 执行记录与恢复

页面展示最近 50 条记录，可继续翻阅更早记录；点开查看持续更新的模型回复、工具结果、触发数据及错误。所有配置、执行记录、事件保存在 SQLite，工具调用另记入审计。服务退出后，正在执行的 AI 任务标记为“取消 / 中断”，不会自动重放可能已经执行的文件修改；未开始的排队任务保留。

AI 配置、任务和日志目前不包含在“设置 → 配置导出”的业务配置文件中。迁移或备份请备份完整数据目录，包括 SQLite 数据库及 `secret.key`；缺少主密钥时不会覆盖已有加密凭据。

## HTTP API

统一前缀 `/api/v1/ai`，全部要求登录，写接口要求 CSRF。`GET /clash`、`PUT /clash` 读取和保存 Clash 配置，读取仅返回 `secret_set`。任务 JSON 支持 `engine`（`pi` / `native`）、`allow_commands`、`allow_network`、`allow_clash`、`test_image`。

| 接口 | 作用 |
| --- | --- |
| `GET /settings`、`PUT /settings` | 读取 / 保存模型接口、默认模型和 models 参数列表 |
| `POST /models/discover` | 以草稿 base_url / api_key 拉取上游模型，不保存 |
| `GET /jobs`、`POST /jobs`、`PUT /jobs/:id` | 列出 / 新建 / 修改任务 |
| `POST /jobs/:id/run` | 手动执行，返回 202 和运行记录 |
| `GET /runs?before=<id>` | 最近 50 条摘要，使用 before 翻阅历史 |
| `GET /runs/:id` | 运行详情与完整输出 |
| `POST /runs/:id/cancel` | 取消待执行 / 执行中的 AI 任务 |
| `POST /events` | 发布自定义事件 |

任务 JSON 示例：

```json
{
  "name": "部署失败分析",
  "prompt": "分析关联项目最近失败的任务日志，并读取配置给出诊断报告。",
  "workspace": "/opt/projects/demo",
  "stack_id": 1,
  "enabled": true,
  "writable": false,
  "allow_actions": false,
  "schedule": "event",
  "event_name": "task.failed",
  "interval_seconds": 3600,
  "daily_at": "09:00",
  "timezone": "Asia/Shanghai",
  "timeout_seconds": 300,
  "max_steps": 15
}
```
