# Git 凭据与 SSH 密钥

栈长第一次启动时会自动生成一把专用的 Ed25519 SSH 密钥，之后所有 Git 操作都使用它。你不需要在宿主机上配置 SSH，也不需要把私钥挂载进容器。

## 密钥位置

密钥保存在数据目录的 `ssh/` 子目录：

| 文件 | 用途 | 权限 |
| --- | --- | --- |
| `<data_dir>/ssh/id_ed25519` | 私钥，只留在服务器 | `0600` |
| `<data_dir>/ssh/id_ed25519.pub` | 公钥，复制到 Git 平台 | `0644` |
| `<data_dir>/ssh/known_hosts` | 已信任的 SSH 主机指纹 | `0600` |

私钥不会通过 HTTP 接口返回。升级、重启或重建容器不会更换密钥，因为数据目录是持久化的。

## 配置步骤

1. 登录栈长，打开 **设置 → Git 凭据**。
2. 点 **复制公钥**。
3. 把公钥添加到代码托管平台：
   - **GitHub 仓库（推荐）**：仓库 → `Settings` → `Deploy keys` → `Add deploy key`，只读权限即可。
   - **GitHub 账号**：`Settings` → `SSH and GPG keys` → `New SSH key`。
   - **GitLab**：仓库 → `Settings` → `Repository` → `Deploy keys`，或用户 `Preferences` → `SSH Keys`。
   - **Gitee**：仓库 → `管理` → `部署公钥`，或账号 `设置` → `SSH 公钥`。
4. 回到 **设置 → Git 凭据**，选择平台并点 **测试连接**。
5. 看到「远程平台已识别这把密钥」后，就可以在项目中执行「检查更新」「拉取代码」「拉取并部署」。

> 公开仓库使用 `https://` 地址时通常不需要配置密钥；私有仓库或 `git@host:owner/repo.git` 地址必须完成上面的步骤。

## 测试连接结果

| 结果 | 含义 | 下一步 |
| --- | --- | --- |
| `SSH 连接成功` | 平台已接受公钥 | 可以正常使用 |
| `Permission denied (publickey)` | 公钥没有加到该仓库/账号，或密钥没有仓库权限 | 重新复制公钥，确认添加到了正确的仓库，并检查 Deploy Key 是否启用 |
| 主机指纹未信任 / 已变化 | `known_hosts` 中没有记录，或平台更换了主机密钥 | 先点「测试连接」记录指纹；如果提示变化，核对平台公告后点「清除已信任主机」 |
| `Could not resolve host` | 容器内 DNS 解析失败 | 检查服务器 DNS 和网络 |
| `Connection timed out` | 无法连接 22 端口 | 检查防火墙/出站规则；GitHub 可改用 HTTPS 公开地址或 `ssh.github.com:443` |
| `工作区存在本地修改` | 项目目录有未提交/未跟踪文件 | 提交、暂存或撤销这些改动后再试；栈长不会执行 `reset --hard` |

任务失败时，弹窗里的错误信息会附带「原因」和「解决」两段说明；如果和公钥/主机指纹有关，还会出现「去 Git 凭据页处理」的快捷按钮。

## 重新生成与清除主机

在 **设置 → Git 凭据** 页面底部：

- **重新生成密钥**：栈长立即改用新密钥，但旧公钥在远程平台的授权不会自动撤销。生成后需要到所有 Git 平台撤销旧公钥并添加新公钥。旧密钥会保留为 `.bak` 文件，便于回滚。
- **清除已信任主机**：清空 `known_hosts`。只有确认平台更换了主机密钥或缓存损坏时才使用；之后第一次连接会重新记录指纹。

## 高级：使用已有密钥

如果你想复用现有密钥，可以停止服务后把文件放到数据目录的 `ssh/` 下：

```sh
sudo install -d -m 700 -o <运行用户> -g <运行用户> <data_dir>/ssh
sudo install -m 600 -o <运行用户> -g <运行用户> <your_key> <data_dir>/ssh/id_ed25519
sudo install -m 644 -o <运行用户> -g <运行用户> <your_key>.pub <data_dir>/ssh/id_ed25519.pub
```

启动后界面会显示这把密钥的公钥和指纹。私钥如果带口令，无法在无人值守的 Git 任务中使用（栈长使用 `BatchMode=yes`），请使用无口令的部署密钥。

## 安全建议

- 优先使用**仓库级 Deploy Key**，只授权需要的仓库，默认只读。
- 不要复用个人日常 SSH 私钥；为栈长单独生成一把，便于随时撤销。
- 数据目录中的 `secret.key`、`zhan.db` 和 `ssh/` 都属于敏感文件，备份时一并保护。

## 密钥一致性与恢复

程序以私钥为准校验公钥；公钥缺失、损坏或与私钥不匹配时会重新派生。私钥损坏，或私钥缺失但仍有旧公钥/私钥备份时，会报错并保留现有文件，避免悄悄改变身份。密钥、备份和主机记录必须是普通文件，不能使用符号链接。

重建密钥时，先准备新文件并复制旧密钥备份，最后替换当前私钥。每次重建仅保留上一份 `.bak`，私钥备份同样使用 `0600` 权限。

内置 SSH 使用独立参数，不读取用户的 SSH 配置或使用 SSH Agent；项目地址应填写实际主机名。非标准端口请使用 `ssh://git@实际主机:端口/仓库路径`，页面的主机连接测试仍使用 22 端口。

`secret.key` 用于解密 SMTP、DuckDNS 和 ACME 等凭据，不能用 SSH 私钥代替。当它丢失且数据库仍有加密凭据时，程序会停止初始化并提示恢复原文件。请从同一份备份恢复数据库、`secret.key` 及 `ssh/`。
