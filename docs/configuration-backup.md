# 配置导入与导出

进入「设置 → 导入导出」。

## 导出

点击「导出配置」，下载带有格式版本的 JSON 文件。内容包括：

- 项目名称、Compose Project Name、目录与 Compose 文件绑定。
- Git origin、分支、轮询间隔、自动部署和通知选项。
- SMTP 连接、发件人、收件人和通知触发条件。
- Nginx 网关监听、代理规则与 DuckDNS 的非敏感设置。
- 日志保留天数。

文件不包含账户、会话、任务历史、日志、SMTP 密码、DuckDNS Token、私钥、证书或 `secret.key`。服务器启动配置（监听地址、数据目录、目录白名单、并发等）由 YAML 或环境变量管理，不在此文件中。导出的是绑定配置，不复制项目代码或 Compose 文件。

## 导入

1. 选择 JSON 配置文件（上限 4 MiB、1000 个项目）。
2. 查看校验后的新增项目数、同名更新数、代理规则数及凭据提示。
3. 点击「确认导入」。

项目按 Compose Project Name 合并：同名项目更新绑定，文件中未包含的现有项目保留；现有项目的运行期望状态和全部任务历史保留。新项目以停止状态记录。SMTP、日志保留设置以及网关和代理规则由文件中的配置替换。

项目目录和 Compose 文件须已存在，并在服务可管理的目录范围内。Git 工作区须位于所选分支，且 origin 与文件中的绑定一致。导入只校验配置，不克隆代码、不切换分支、不启动容器或申请证书。

所有配置一次性保存。校验失败、项目有排队或执行中的任务、网关正在执行任务时，不会部分导入。如果从预览到确认期间配置发生变化，需要重新校验。

导入后，涉及项目的定时检查和自动部署均暂停，可在项目设置中重新开启。Nginx 需到「反向代理」手动应用配置；证书需在目标服务器另行申请或通过完整数据备份恢复。

本机已保存的 SMTP 密码，仅在 SMTP 地址、端口、用户名和 TLS 模式一致时沿用；DuckDNS Token 仅在主域名一致时沿用。其他情况以及迁移到新服务器时，需要重新填写凭据。

完整数据备份仍需停止服务后备份整个数据目录，参见[安装文档](install.md)。

## API

- `GET /api/v1/settings/config/export`：下载配置 JSON。
- `POST /api/v1/settings/config/import/preview`：请求体为配置 JSON，返回校验摘要和当前配置版本标识 `revision`。
- `POST /api/v1/settings/config/import`：请求体为 `{"backup": <配置 JSON>, "revision": "<预览返回的标识>"}`。

所有接口要求已完成首次改密的管理员会话，两个 POST 接口还要求 CSRF Token。配置文件使用 `format: "zhan-config"`、`version: 1`，未知字段和不支持的版本会被拒绝。
