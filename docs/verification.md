## 关键行为

- 构建失败不继续 up，不更新成功部署 Commit；旧服务运行状态单独读取。
- 手动停止整个项目后自动部署暂停，轮询检查仍可继续。
- 取消 Running 任务后，等待子进程退出才释放项目锁。
- 相同项目最多一个 Pending / Running 任务，同一工作目录互斥。
- 脏工作区拒绝更新，Git 仅快进合并；成功 Git Pull 不等于部署成功。
- 已停止容器的残留 Health 值不会被误报为运行中的健康故障。
- 健康等待失败单独记录在 `healthcheck` 阶段，成功版本不会提前推进。
- SMTP 密码加密存储且不通过 API 返回，常见日志密钥格式脱敏。

## 仍需在实际服务器验收

- 目标 Linux 的 systemd、Docker 权限、受管项目真实路径与 SSH 身份。
- 实际 SMTP TLS 服务器和收件人配置。
- 10–30 项目的长期运行、RSS 与日志/数据库增长。设计文档中的内存目标不是实测结果。
- 业务应用自身的构建过程与健康检查配置。V1 不承诺自动回滚和零停机部署。

初始化流程更新：首次自动生成 `admin / 123456`，未改密会话被服务端限制；覆盖初始密码登录、管理接口拦截、CSRF、新密码校验、会话全部失效、新密码登录和再次启动不覆盖密码的回归测试。

服务器路径选择器：默认无目录白名单；支持目录浏览、上级导航、路径粘贴、隐藏目录、分页、多选 YAML/YML/JSON 与常见 Compose 文件识别。接口测试覆盖登录与首次改密门禁、只读元数据、分页、符号链接、显式范围和外部 Compose 覆盖文件。
