# 密钥与 Go 风格检查记录

检查基于 Go 1.26.0，覆盖内置 Git SSH 身份、加密主密钥、凭据调用、日志脱敏，以及后端格式和常用写法。

## 已修复的问题

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 重建前先移走旧私钥 | 后续失败时原身份可能不可用 | 复制备份，准备新文件，最后替换私钥；失败时恢复公钥 |
| 使用固定 `.tmp` 文件名 | 残留文件或符号链接可能让私钥写到错误位置 | `os.Root` 限制目录范围，随机临时文件独占创建，写入后同步并替换 |
| 直接信任已有 `.pub` | 界面可能显示与实际认证私钥不同的公钥 | 每次从私钥派生并校验公钥缓存；私钥损坏明确报错 |
| 忽略部分权限修复错误 | 私钥、备份或主机记录可能保持不合适权限 | 拒绝非普通文件，检查权限修复结果，私钥及备份固定 `0600` |
| `secret.key` 丢失后重新生成 | 已保存凭据变得无法解密 | 有加密凭据时拒绝生成替代密钥，提示恢复原密钥；检查既有文件权限和长度 |
| 测试和 Git 调用的 SSH 参数不一致 | 带空格路径、用户 SSH 配置和其他身份影响认证结果 | 共用参数；正确处理 SSH 配置字符串和路径；隔离用户配置与 Agent |
| SSH 测试先无限读取输出再截断 | 截断前仍可能占用大量内存 | 有界输出、执行超时、进程组清理，并对返回内容脱敏 |
| 私钥 PEM 未覆盖到脱敏规则 | 测试结果或命令日志可能包含私钥文本 | 完整文本与跨写入、跨行日志均过滤私钥块 |
| 宣称重建后旧公钥立即失效 | 用户可能误以为远程授权已撤销 | 明确提示到 Git 平台手动撤销旧公钥 |

密钥文件需要固定路径和明确替换语义，因此这里使用标准库的受限目录与原子替换；没有增加自动冲突改名的文件管理依赖。

## 风格优化

- 全部后端 Go 文件统一 `gofmt`，导入按标准库、外部依赖、项目内部依赖分组。
- 在适用位置改用 `slices.Sort`、`slices.SortFunc` 和 Go 1.26 的 `errors.AsType`。
- 移除 Go 1.22 后多余的循环变量重新绑定。
- AES/GCM 初始化、密钥写入、同步和关闭错误显式处理。
- `scripts/check.sh` 增加格式检查，避免未格式化代码进入后续改动。

## 验证

- 后端全量 `go test -race ./...` 与 `go vet ./...`。
- 真实 OpenSSH `ssh -G` 参数解析，使用临时目录，不连接外部平台。
- 公私钥不匹配、损坏、缺失、备份、符号链接、文件权限、失败清理、受限输出和脱敏回归测试。
- 加密主密钥丢失、错误长度、符号链接、权限修复与密文篡改测试。
- 前端测试与生产构建。

以上验证使用临时测试数据；远程 Git 平台授权与真实网络连通性仍由管理员通过页面测试确认。
